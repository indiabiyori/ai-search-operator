# AI 検索の観測ブリーフ

最終更新日: [要追加: YYYY-MM-DD]

ai-search-operator が観測の条件をそろえ、回答の正誤を判定し、施策を事業の目標に結びつけるための前提情報。スキルフォルダの中のこのテンプレートは編集せず、作業フォルダの `ai-search/brief.md` にコピーして記入する。

- 未記入の値は `[要追加: ○○]` のまま残す。推測で埋めない。
- 公開ページなどから推測して下書きした値には `[要確認: ○○（根拠: URL）]` を付け、確認が取れたら外す。
- 「記入ガイド」の列と行は、記入後も残してよい。
- 自社と競合の表記ゆれ・除外語・ドメインは、このファイルではなく `ai-search/entities.csv` に書く。
- AI サービスの画面や規約のように時間がたつと変わる事実は、このファイルに写さない。スキルの `references/` の中の参照先と、確かめた日だけを書く。
- 記入の方法は `references/01-setup.md` を参照する。

## 3. 観測の条件の決まり

### 観測する組

| service | surface | login | mode | region | language | 備考 |
|---|---|---|---|---|---|---|
| [要追加: 例 chatgpt] | web | なし | [要追加: 例 検索あり] | JP | ja | [要追加: 表示されたモデル名など] |
| [要追加: 例 google-ai-mode] | web | なし | [要追加: モード] | JP | ja | [要追加: 備考] |

- 記入ガイド: 1行が集計の1組になる。surface・login・region・language の値は既定（web、なし、JP、ja）を入れてある。変えるなら書き換える。
- service の値は `chatgpt` / `claude` / `gemini` / `copilot` / `google-ai-mode` / `google-aio`、surface は `web` / `app` / `api`、login は `なし` / `あり（記憶オフ）` / `あり` のどれか。`perplexity` は、既存の回答ファイルを読むために残してある値で、一般向けの画面での新しい観測には使わない（下の「観測しないサービスと理由」）。
- login と mode は、`references/03-observation.md` の「サービスごとの既定の案」から選ぶ。案のもとにした公式資料と確認日は、`references/services/` のサービスごとのファイルにある。
- mode の欄には、回答ファイルの `mode` に書く文字列をそのまま書く。ラウンドの前に決め、以後変えない（書き方は `references/03-observation.md` の「ラウンドの決まり」）。
- 備考には、表示されたモデル名やモードの名前を書く。サービスごとのファイルの「観測するときの手順」が brief.md に書くよう求めていること（どの画面で尋ねたか、など）も、ここに書く。プロンプトに検索を指示する文を足したなら、その文をそのまま書き、全回答で同じ文を使う（`mode` は `検索指示あり`）。
- 最初は2サービスから始める（規模の目安は `references/02-prompt-set.md`）。条件のそろえ方（記憶やパーソナライズのオフ、検索モード）は、03 の「サービスごとの既定の案」と `references/services/` のサービスごとのファイルにある。
- 条件の違う回答は別々に集計する。組を途中で変えたら更新履歴に書き、変える前と後を混ぜて比べない。

- 記入ガイド: 対象にしなかったサービスと理由を残す。規約や画面の事実は写さず、参照先を書く。確かめた日には、参照先を読んで理由を確かめた日を書く。
- perplexity の行は最初から入れてある。非対応の理由と規約の要点は、参照先のファイルにある。API や Enterprise の規約、または Perplexity の書面による許可のもとで観測するなら、その条件を利用者が確かめる。確かめたら、規約か許可の名前、観測を認める根拠の箇所、確かめた日を「最初の観測で確かめたこと」に書き、この行を消す。法的な判断は専門家に確認する。
